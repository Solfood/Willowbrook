# DEC-0001: Adopt engineering scaffold for AI-assisted development

- Date: 2026-04-24
- Status: accepted
- Owner: Solfood
- Marker: WB-DX-0001
- Supersedes: N/A

## Context

Willowbrook is developed iteratively with AI assistance. The repo already has good architecture documentation (ARCHITECTURE_AND_DATA_PLAYBOOK.md, DEV_NOTES.md) but no lightweight work-tracking or session-continuity mechanism. Each AI session has to re-derive context from the existing docs rather than picking up from a known state.

## Intake

- Objective: Add a session-continuity layer (work-index, session-log, decision records) that complements the existing architecture docs.
- In scope: CLAUDE.md, policies/project-policy.yaml, docs/work-index.md, docs/session-log.md, docs/decisions/ directory.
- Out of scope: Changes to application code, test suite, CI/CD, or existing playbooks.
- Risk class: low
- Critical assets touched: none
- Dependencies: engineering-scaffold-template (Solfood/engineering-scaffold-template)
- Expected evidence: All scaffold files present, no placeholder strings remaining.

## Options Considered

1. **Extend existing playbooks** — playbooks are design/ops docs; mixing work-tracking into them degrades both.
2. **Engineering scaffold template** (chosen) — adds exactly the session-continuity layer that's missing without touching the existing docs.

## Decision

Adopt the engineering scaffold. The existing ARCHITECTURE_AND_DATA_PLAYBOOK.md and DEV_NOTES.md remain the primary architecture reference; the scaffold adds work-tracking and session continuity on top.

## Why

The existing docs cover the "what and why" of the architecture well. What's missing is continuity between sessions: what's in progress, what was decided last time, and what the next step is. The scaffold fills exactly that gap.

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| Duplication with existing playbooks | Scaffold docs are additive — no content is duplicated; DEC records can link to playbook sections |

## Rollback Plan

Delete CLAUDE.md, policies/, docs/work-index.md, docs/session-log.md, docs/decisions/. Existing playbooks are unaffected.

## Evidence

Scaffold files created and verified. Policy risk tolerance set to low (no server, no auth). Suite block references bluray and recipes-wiki.
